# Artefact System — Kern (Chunk 1) Design

**Date:** 2026-06-06 · **Author:** Liz (with Chris) · **Block:** 2 (→ v0.1.0) ·
**Side:** client-only (no Larissa gate; see §11)

> Chunk 1 of the artefact system. The overall plan, decision log, and
> decomposition live in [[../../obsidian/ARTEFACTS-FEATURE-STATUS]] — read it
> first. This spec details the **Kern** only: model-driven generation of
> single-file web-app artefacts, the in-stream pill, opening in the lightbox, and
> the per-chat sidebar. Treasury, attachments, save-as, iteration, and the
> configurable author model are later chunks.

---

## 1. Goal

Let a persona produce a **single self-contained HTML file** as a durable,
reusable artefact, generated by a focused **author subagent** so the heavy file
never burdens the main conversation. The user sees a live "building…" pill, taps
it to open the artefact in the existing lightbox (view / edit source / rename /
copy / download / delete), and finds all of a chat's artefacts in a compact
sidebar — behaving like the existing ToC sheet.

## 2. Scope

**In:**
- `artefacts` Dexie table (migration v13).
- An **author subagent** (one-shot completion) that turns a brief into a
  single-file HTML document, streamed.
- A `create_artefact` tool, contributed as an always-on integration.
- Tool-loop wiring so the tool runs, streams character progress into its pill,
  and persists the artefact.
- The artefact **pill** (variant C) in the chat stream; tap → lightbox.
- **Lightbox** reuse for artefacts (`ViewableItem` bridge, caps incl. delete +
  dual rename).
- A compact per-chat **artefact sidebar** opened from the `ReadingToolStrip`.
- Deletion + pill **tombstone**.

**Out (later chunks — see STATUS §4):** Treasury (2), artefacts-as-attachments
(3), save-message / save-code-block as artefact (4), `edit_artefact` iteration
(5), configurable author model (6), `read_artefact`, vector search.

## 3. Architecture overview

```
user: "build me a calculator"
        │
   main model (persona's LLM)  ── streams prose ──▶ chat stream (content blocks)
        │  emits tool call: create_artefact({title, brief})
        ▼
   tool-loop ── dispatch ──▶ create_artefact.execute(args, signal)
        │                         │
        │                         ├─ resolve persona offering + key (from ctx)
        │                         ├─ author subagent: one-shot completion,
        │                         │   system="single self-contained HTML file…",
        │                         │   input=brief  ── streams content ──┐
        │                         │                                     │
        │   onPillUpdate(chars) ◀─────────────────────────────────────┘  (live)
        │                         ├─ strip ```fences, build ArtefactRow
        │                         ├─ persist to Dexie `artefacts`
        │                         └─ return ToolResult: "created artefact «title» (id)"
        ▼
   pill (variant C) finalised in the persona message  ── tap ──▶ lightbox
        ▲
   sidebar (ReadingToolStrip) ── reactive query on artefacts(chatId) ──┘
```

The main model only ever sees the brief (its own tool-call args) and the terse
result string — never the file body (decisions #5, #14, #17).

## 4. Data model — `artefacts` table (Dexie **v13**)

Current schema is v12 (`boot/client-data-db.ts`). Add one table; no changes to
existing tables. Shaped to mirror `attachments` so the `ViewableItem` bridge is
trivial and image artefacts (TTI) fit later without a migration.

```ts
interface ArtefactRow {
  id: string;                  // pk (addressable — iteration uses it later)
  chatId: string;              // owner (cascade-deleted with the chat, §10)
  personaId: string;           // provenance + future treasury filter
  projectId: string | null;    // reserved; unused until projects exist
  origin: 'generated';         // 'saved-message' | 'saved-code-block' arrive in chunk 4
  kind: 'text';                // 'image' reserved for TTI
  format: 'html';              // widens to md|code|svg|mermaid|image via other paths
  title: string;               // display name, freely renameable
  fileName: string;            // carries extension (download + detectFormat); renameable
  mime: string;                // e.g. 'text/html'
  content: string;             // the file
  tags: string[];              // reserved (Treasury chunk owns the UI); [] for now
  favourite: boolean;          // sidebar/treasury pin
  createdAt: number;
  updatedAt: number;
}
```

Indexes (provisional, confirm in plan): `id, chatId, personaId, favourite,
[chatId+createdAt]`. Migration: pure table-add, no backfill. Bump every existing
"fresh-open verno" assertion 12 → 13 (the established pattern from prior bumps).

`title` vs `fileName` (decision #16): on create, `fileName` is auto-derived
(slug of `title` + `.html`); both are independently editable thereafter. Download
uses `fileName`; the lightbox preview format derives from `fileName` via the
existing `detectFormat`.

## 5. Author subagent

New module (`lib/artefact-author.ts` or similar). Reuses the one-shot wire path
already used by `lib/title-generator.ts` and `attachments/substitute-vision.ts`
(`composeOneShotWire` → streamed completion through the persona's adapter).

- **Inputs:** the persona's resolved LLM offering (provider + model), a key
  getter, the `brief` string, an `AbortSignal`, and an `onProgress(chars)`
  callback.
- **System prompt (focused, the load-bearing single-file enforcement):**
  "You are a single-file web-app author. Output **exactly one** self-contained
  HTML file and nothing else. Inline all CSS and JavaScript. **No** external
  resources — no CDN, no `<script src>`, no `fetch`/network, no imports.
  Mobile-first (works at 380 px). Output only the file, no prose, no
  explanation." (Final wording tuned in the plan; British English.)
- **Streaming:** consume content deltas, count characters, fire `onProgress` so
  the pill shows a live count. Content always streams (unlike tool-call args on
  some upstreams — decision #14b), so progress works on every adapter.
- **Post-process:** strip a leading/trailing ```html / ``` fence if present;
  trim. Store whatever remains as `content` (we cannot truly enforce "one file",
  but the system prompt + fence-strip handle the realistic cases).
- **Errors:** provider error / empty output / abort → throw; the tool maps it to
  a failed `ToolResult` with a constructive message; the pill goes `failed`.
- **Author model = the persona's model** for now (decision #14; configurable
  picker is chunk 6).

## 6. `create_artefact` tool + registration

`Tool` shape (`tools/types.ts`): `name`, `description`, `parameters` (JSON
Schema), `systemPromptInstruction`, `execute(args, signal)`.

- **Params:** `{ title: string, brief: string }`.
- **`description` / `systemPromptInstruction`:** tell the main model to use this
  for substantial interactive HTML the user may want to keep/iterate/share, and
  — critically — to pass a **complete, self-contained brief** (all requirements,
  content, and styling intent), because a separate author produces the file from
  the brief alone (mitigates the telephone-game risk, decision #14).
- **`execute`:** runs the author subagent, streams progress via the pill-update
  channel, persists the `ArtefactRow`, returns
  `{ ok: true, output: "created artefact «title» (id: <id>)" }`.

**Registration — the mechanism to resolve in the plan.** `execute` needs the
per-send context (persona offering + `getKey`), but static tools (`calculate_js`)
receive no ctx and `Tool.execute` has no ctx param. Two clean options:

1. Contribute `create_artefact` from an **always-on artefact integration**
   (`integrations/artefact/`) whose `contributesTools(ctx)` closes over ctx —
   mirrors `webIntegration`. Requires extending `IntegrationContext` with the
   persona's **LLM offering** (today it carries web refs, cors, nsfw, `getKey`
   but **not** the persona model). `buildIntegrationContext(persona, …)` already
   has the persona, so it can add `personaOffering: OfferingRef`.
2. Extend the static-tool path to accept ctx.

Recommend option 1 (consistent with the existing integration seam). The tool is
contributed whenever `offering.profile.toolCalls.supported` (existing gate);
non-tool models are not curated anyway (decision #13).

## 7. Tool-loop integration & the pill (variant C)

The tool-loop (`lib/tool-loop.ts`) already: injects tool defs, detects tool-call
pills, dispatches, sets pill status `pending → completed/failed`, and mirrors
status into the streaming draft via `onPillUpdate` (`stream-manager.store.ts`).

- The artefact pill is an ordinary `pill` content block in the persona message
  (like `calculate_js`). Payload: `{ artefactId, title, format, charCount,
  status }`.
- During authoring, `execute` reports character counts; we route them through
  the existing `onPillUpdate` channel so the pill shows the live count + sweep
  bar (variant C, `pending`).
- On success the pill is `completed`: "N chars · tap to open ↗". The pill exposes
  a `data-*` attribute so the lightbox can resolve its origin rect for the FLIP
  zoom (mirrors `data-attachment-thumb`).
- **No stream text is authored by us** (decision #19): the surrounding prose is
  the model's own content blocks.

Pill rendering lives in `components/chat/Pill.tsx`; add the artefact kind (icon,
serif title, format chip, progress, tap-to-open) and the click → open-lightbox
handler.

## 8. Lightbox integration

The unified lightbox (`components/lightbox/`) takes `ViewableItem[] + index +
caps + getOriginRect + onRename/onRemove/onEditText/onClose`.

- **Bridge:** an `artefactToViewable(row)` helper (sibling of
  `attachmentToViewable`) → `{ id, kind:'text', fileName, mime, text: content,
  caps }`. Format/preview derive from `fileName` via `detectFormat` → HtmlPreview
  (the hard sandbox, §11).
- **Items set / cycling (decision #10):** opening from a pill (or sidebar) passes
  **the chat's artefacts** as the items array, index at the chosen one, so the
  user can page through them.
- **Caps for a generated artefact:** `rename: true`, `editSource: true`,
  `copy: true`, `download: true`, `delete: true`. (`remove` — the
  pending-upload-only cap — stays false.)
- **Dual rename (decision #16):** the lightbox needs two rename targets — a
  prominent editable `title` and a smaller editable `fileName`. Today
  `onRename(id, name)` edits a single name. Extend the lightbox rename UI +
  callback to carry both (e.g. `onRename(id, { title, fileName })`), or add a
  second callback. Resolve the exact shape in the plan; keep the attachment path
  unaffected.
- **Edit source** → `onEditText(id, text)` saves to `artefacts.content`
  (`updatedAt` bumped). **Delete** → `onDelete`/`onRemove` for generated origin
  removes the row (§10).
- All mutations go through TanStack Query mutations that invalidate the
  `artefacts(chatId)` query, so pill / sidebar / lightbox stay consistent.

## 9. Sidebar (variant A — compact)

Mirrors the ToC sheet (`components/chat/TocSheet.tsx` + `ReadingToolStrip.tsx`).

- A **new button** in `ReadingToolStrip` beside the ToC `◈` opens an
  `ArtefactSheet`. Strip state already supports collapse/pin (`useCurrentChatStore`).
- **Layout (decision #20):** compact one-line rows — format-coloured glyph +
  `title` + favourite star. Two sections: **★ Favourites** (starred) and **In
  this chat** (newest first). A starred artefact appears in both (lossless,
  mirrors ToC pinned+timeline).
- **Interactions:** tap → lightbox (same items/cycle as §8); star toggles
  `favourite`; inline rename edits `title` (the sheet only needs the display
  title; `fileName` lives in the lightbox).
- **Reactivity:** a `useChatArtefacts(chatId)` query (TanStack Query over Dexie,
  `liveQuery` or invalidation) so renames/edits/favourite/delete reflect live —
  the STATUS requirement that the sidebar mirror lightbox changes.
- **Auto-open on first artefact:** optional, low priority — decide in plan
  (Chatsune auto-opened the sidebar on the first artefact). Default: do **not**
  auto-open (calmer; mobile-first), surface via the strip button + the pill.

## 10. Deletion & tombstone

- Deleting an artefact removes the `ArtefactRow` and invalidates
  `artefacts(chatId)` → the sidebar row disappears.
- The in-stream pill referencing a now-missing artefact renders a **tombstone**:
  greyed, "Artefact deleted", non-clickable. (Lookup by `artefactId` returns
  nothing → tombstone state.)
- **Chat deletion cascades** (decision #15): deleting a chat deletes its
  artefacts. The chat-delete flow gains a warning when the chat has artefacts
  ("this will also delete N artefacts"). Implement the cascade + warning in the
  existing chat-delete path.

## 11. Security

Client-only → no Larissa gate (§9 CLAUDE.md). **But** we now persist
model-generated, *executable* HTML and render it. The control is the existing
`HtmlPreview` sandbox: iframe `allow-scripts` **without** `allow-same-origin`
(null origin — no cookies/localStorage/IndexedDB/MK access) + CSP
`default-src 'none'` (no external network → no IP leak). The author system
prompt forbids external resources, but the sandbox is the real boundary (defence
in depth — never trust the model's output). Log the new persisted-execution
surface in [[../../obsidian/insights/security-deferrals]] when this lands.

## 12. Testing

Backend-less feature; Vitest (frontend).

- **Author subagent:** unit tests with a stubbed completion — fence-stripping,
  progress callback fires, abort/empty/error → throw.
- **`create_artefact.execute`:** stubbed author → persists a correct
  `ArtefactRow`, returns the terse result (no file body), maps errors to a failed
  result.
- **Dexie v13:** migration opens at verno 13; existing verno assertions bumped.
- **Bridge:** `artefactToViewable` produces correct caps + format.
- **Sidebar:** renders favourites + chat sections; star/rename/tap behave;
  reactivity on mutation.
- **Pill:** building (progress) vs completed (tap-to-open) vs tombstone states.
- Per the Chatsune lesson, per-task review runs the **full** Vitest suite, not
  just touched dirs ([[feedback_per_task_review_runs_full_suite]]).

## 13. Manual verification (Chris, on device)

1. Ask a persona (tool-capable model) to "build me a small calculator". A pill
   appears and shows a **live character count** while building (verify on an
   adapter that does *not* stream tool-call args, e.g. Ollama Cloud native).
2. The surrounding prose ("I'll build you…", "…done, have fun") is the model's,
   reads naturally, and the pill sits inline — nothing injected by the app.
3. Tap the pill → the calculator opens in the lightbox, **renders and is
   interactive** (buttons work) inside the sandbox.
4. Edit the source (e.g. change a colour) → Save → reopen shows the change.
5. Rename the **title** and the **filename** independently; Download yields the
   renamed `.html`.
6. Open the artefact sidebar from the reading-tool strip → the artefact is
   listed; star it → it appears under Favourites; rename inline → reflects
   everywhere.
7. Delete the artefact → the sidebar row vanishes and the in-stream pill becomes
   a non-clickable tombstone.
8. Delete the whole chat → the warning names the artefact count; after delete the
   artefacts are gone.
9. A maths-free / artefact-free chat is unchanged.
