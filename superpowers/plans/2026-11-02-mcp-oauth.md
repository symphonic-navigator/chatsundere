# OAuth for MCP connectors Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task by task. If skills are unavailable, emulate it with the plain Agent tool. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user connect any spec-following MCP server with a link and an OAuth sign-in, with tokens synced between devices as ciphertext.

**Architecture:** A client-side OAuth module under `apps/user-client/src/mcp/oauth/`. Tokens live in a new sealed sync collection, `mcpOAuthGrants`. Refreshes are serialised across devices with a sealed claim on the sync server's existing per-record compare-and-set. The proxy only gains exposed response headers.

**Tech Stack:** TypeScript strict, React 18, Dexie, Vitest (user-client), Bun test (proxy-service), Hono, nginx.

**Spec:** `superpowers/specs/2026-11-02-mcp-oauth-design.md`. Read it before Task 1: every task implements a section of it, and section numbers below refer to it.

## Global Constraints

- All text in the repository is British English: code, comments, identifiers, commit messages, copy (`colour`, `behaviour`, `authorise`).
- Licence header on new files under `apps/`: `// SPDX-License-Identifier: AGPL-3.0-only`.
- TypeScript `strict` and `noUncheckedIndexedAccess`. No `any` without an inline comment saying why. Package-public functions carry a one-line JSDoc. Comments explain why, never what.
- Commit messages: free-form imperative, capitalised subject, no Conventional Commits prefix. Every commit ends with the line `Co-Authored-By: Liz (Claude Code) <noreply@anthropic.com>`. Doc-only commits append `[skip ci]` to the subject.
- UI: mobile-first at 380 px. No drag-and-drop. Disabled with a reason, never silently hidden. Use the `Button`, `ConfirmDialog` and `PageScaffold` primitives.
- Tokens, codes and verifiers never reach logs, `console.*`, error messages, test assertion output or reports.
- HTTPS only for all OAuth endpoints and the MCP URL of an OAuth server; loopback `http` only when `import.meta.env.DEV` is true.
- Constants: claim lease 5 minutes, by local observation only; refresh request timeout 20 s; lost-response retry window 25 s; a tool call waits for a foreign claim at most 20 s; pending sign-in lifetime 10 minutes; callback acknowledgement wait 1.5 s; proactive refresh when under 60 s remain; auto-return after unlock only within 2 minutes.
- Paste format: `csm1.` + base64url of JSON `{ code, state, iss }` or `{ error, state }`.
- Subagents never merge, push or switch branches. Subagents leave their work uncommitted; the controller commits and pushes after each task's reviews pass. Verify with `git branch --contains HEAD` that it landed on `feature/mcp-oauth`.
- **Mutation discipline.** `git checkout -- <file>` restores from the index, so stage first: run `git add <the task's paths>` once the tests pass, then break one thing, run the task's test command, see a test fail, and restore with `git checkout -- <file>`. Run mutations before the commit, one at a time.
- Commands assume the toolchain is on `PATH`; with `mise`, prefix them with `mise exec --`.

## Review Focus

1. Device clocks that disagree by minutes: claims are judged by local observation, and a skewed token expiry degrades to a reactive refresh, so skew never produces two presented tokens. Test in Task 6.
2. A token response without `expires_in`: `accessExpiresAt` is null, the token is used until a 401 arrives, then refreshed once. Test in Task 6.
3. A link pasted with a trailing slash, uppercase host or default port: the same `resource` everywhere (Task 2), and connecting a link whose canonical form an existing OAuth row already has points the user to that row rather than making a second identity (Task 10).
4. The master key disappears (the app locks and zeroes it in place) between claim and publish: the private key copy still seals the fresh pair into `pendingTokens`, and without a key at the start no claim is taken. Test in Task 6.
5. Hostile metadata: non-JSON, huge, or `javascript:`/`data:` endpoints from a server the user does not fully trust: refused before use, with a readable message. Test in Task 3.
