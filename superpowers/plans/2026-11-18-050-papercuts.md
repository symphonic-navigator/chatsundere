# 0.5.0 papercuts — implementation plan

**Spec:** [`superpowers/specs/2026-11-18-050-papercuts-design.md`](../specs/2026-11-18-050-papercuts-design.md) (approved by Chris, 2026-11-18). The spec is the source of truth for behaviour and copy; this plan only cuts it into tasks and fixes the order. Every task reads the spec sections it names before touching code.

**Branch:** `feat/050-papercuts`. All work in `apps/user-client` (and one test file, Task 6). Subagents edit files and run tests; **they never commit, merge, push or switch branches**. Liz commits after each wave.

**Gates per task:** `pnpm --filter @chatsundere/user-client exec vitest run <touched test files>` green, `pnpm --filter @chatsundere/user-client typecheck` green, `pnpm exec biome check <touched files>` clean. Full gates (`pnpm test`, `pnpm typecheck`, `pnpm run build`, `pnpm lint`) at the end.

**Rules for every task:** British English in all text. Copy exactly as the spec gives it (the builder may shorten, keeping content). No change to what is sent to a provider (spec "Prompt-cache consistency"). Do not touch: the History entry of `ChatQuickMenu.tsx` (another session changes it), how `PageBar`'s Back works in general, `src/index.css` beyond small local additions, the sense-of-time switch, chat export, reduce-animations, History search, voice wake lock / lock-screen controls / touch sizes. Tests follow the existing patterns in `apps/user-client/tests/`.

## Task 3 — Typed send errors and the passphrase way out (spec: items 7, 9; item 6's last two key-test cases)

Files: `data/send-message.ts`, a new `data/send-errors.ts` (the two error classes), `routes/app/chat/chat-page.tsx`, `components/chat/Cockpit.tsx` (note slot), the in-stream notice components for opener/regenerate, `routes/login/index.tsx`, `memory/resolve-args.ts`, `memory/classify-error.ts`, `routes/app/persona-memory.tsx`, `routes/app/settings/provider.tsx` (catch mapping + focus key field when opened from Re-enter key, e.g. `?focus=key`).

1. `ProviderKeyLockedError { templateId, providerName }` and `MasterKeyUnavailableError`; thrown in `resolvePersonaContext` and `resolvePersonaBundle`; no key material in them.
2. Send: resolve the context **before** creating a new chat's row. Interrupted-reply Retry: resolve **before** the deletes; on a typed failure delete nothing. The draft stays.
3. Notes: cockpit slot for send; in-stream notice for opener and regenerate (both modes). Exact sentences and actions from the spec.
4. Login `need=passphrase`: passkey button disabled with "This needs your passphrase", passphrase field focused, "Not now" to the validated return target while a session is active. Without `need`, unchanged.
5. Memory: `key-locked` code with Re-enter key; `no-credentials` copy + Enter passphrase; classifier by `instanceof`.
6. Provider page: `OperationError` → "The saved key can't be opened any more. Paste it again."; missing mk → passphrase sentence + Enter passphrase.
7. Tests: typed errors thrown; notes shown in both modes; draft kept; no chat row on a failed first send; Retry deletes nothing on failure; login `need=passphrase` behaviour; memory codes; provider mapping. A test pins that a successful send builds the same request as before (wire unchanged).
