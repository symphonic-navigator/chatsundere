# TEAL v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add mood tags (emotions and companion tones) and six new sounds to TEAL, give each TTS offering a TEAL level, render moods as emojis, and make Copy give what the user sees.

**Architecture:** The vocabulary and the level-aware strip live in `packages/llm-unified/src/teal`. Offerings declare `teal: 'none' | 'v1' | 'v2'`. Segmentation carries a paragraph's mood across sentence-mode segments. The client render map gains a mood table, rendered as labelled emoji spans. Copy runs a display-plain-text transform.

**Tech Stack:** TypeScript strict, bun test (llm-unified), Vitest (user-client), Biome.

**Spec:** `superpowers/specs/2026-11-16-teal-v2-design.md` (approved 2026-11-16). TEAL v1 spec: `superpowers/specs/2026-06-11-teal-voice-expression-language-design.md`. Section numbers below refer to the v2 spec.

## Global Constraints

- British English in every identifier, comment, test name and string (CLAUDE.md §3.7). Tag names are English, lower case, hyphenated.
- SPDX headers: `LGPL-3.0-only` in `packages/llm-unified`, `AGPL-3.0-only` in `apps/user-client`.
- The vocabulary stays closed: unknown brackets stay literal (v1 D2).
- Tests are structural; never phrase-match prompt prose beyond markers (CLAUDE.md §13).
- Every package-public function carries a one-line JSDoc; no `any` without reason; `noUncheckedIndexedAccess` is on.
- Commit after each task on the current branch. Subject capitalised, no Conventional Commits prefix, trailer `Co-Authored-By: Liz (Claude Code) <noreply@anthropic.com>`. **Subagents never merge, push or switch branches.**
- Gates at the end: `pnpm test` (auth-service and sync-service need Postgres; run the rest with `--filter`), `pnpm typecheck`, `pnpm run build`, `pnpm exec biome check .`.

## Review Focus

1. **Common English words in brackets** (`[content removed]`, `[tired of this]`, `[sad but true]`): they stay literal in chat, copy and speech. Tested in Task 1.
2. **A sentence-mode paragraph that starts with a mood** on ElevenLabs: every later segment of that paragraph carries the mood; the next paragraph starts neutral. Tested in Task 3.
3. **A v2 tag sent to Grok or Mistral:** it is never in the request body. Tested in Task 2.
4. **Copy on a message with a code block containing `[sad]`:** the code keeps `[sad]` literally, and the prose gets emojis. Tested in Task 5.
5. **A half-typed mood at the stream tip** (`[ner`): it is suppressed, not flashed. Tested in Task 4.
