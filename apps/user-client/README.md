# @chatsundere/user-client

The Chatsundere user-facing PWA. Local-first: a Chatsundere account can be created and used entirely on-device, with no server. Linking to a backend is optional and additive. The server only ever sees ciphertext; it cannot see passphrases, master keys, or recovery keys.

Mobile-first at 380 px viewport with a single `lg` breakpoint at 1024 px. Tailwind v4. React 18 + TypeScript (strict). TanStack Query + Zustand. WebAuthn PRF for biometric unlock (per [ADR 0005](../../obsidian/decisions/0005-require-prf-for-passkey-mk-wrapping.md), PRF-less passkeys are refused). Vite + `vite-plugin-pwa` + Workbox for the PWA shell.

See the spec at `superpowers/specs/2026-05-18-foundational-auth-layer-design.md` for the full design.

## Prerequisites

- pnpm 9+ and Node 20+ for the build toolchain (Vite runs under Node).
- A linked backend is optional; the user-client functions stand-alone in local-only mode.

## Scripts

```bash
pnpm --filter @chatsundere/user-client dev          # http://localhost:3000
pnpm --filter @chatsundere/user-client build        # production build to dist/
pnpm --filter @chatsundere/user-client preview      # serve the production build
pnpm --filter @chatsundere/user-client typecheck    # strict TS + test typecheck
pnpm --filter @chatsundere/user-client test         # vitest run
pnpm --filter @chatsundere/user-client test:watch   # vitest in watch mode
pnpm --filter @chatsundere/user-client generate:icons   # regenerate placeholder PWA icons
```

## What it does today (phase 0)

- **Local-first onboarding.** Three-step wizard: username, passphrase, recovery key reveal with confirm-stored gate. The recovery key is shown exactly once; lose it and the data on this device is gone (no-recovery is a feature, see [ADR 0007](../../obsidian/decisions/0007-recovery-key-required-at-registration.md)).
- **Local login.** Passphrase entry. Biometric unlock (WebAuthn with PRF) when a passkey has been set up and the platform supports user-verifying platform authenticators. "Forgot passphrase?" leads to the recovery flow.
- **Recovery flow.** Recovery-key entry plus forced new passphrase. Linked accounts can choose between local-only recovery (server-side stays signed out until next link) or full server recovery. Optional regenerate-recovery-key with reveal-once gate.
- **Settings (four tabs).** Account (rename, delete-local-data with typed-username confirm), Authentication methods (passphrase row, per-biometric rename/remove with last-method lockout guard, regenerate recovery key), Server linking (state-aware: not linked / linked / offline-blocked), About (version, licence, docs).
- **Server linking.** QR scan (via `BarcodeDetector` where available, `qr-scanner` fallback) or paste an invitation URL. Runs OPAQUE-first registration ([ADR 0021](../../obsidian/decisions/0021-phase0-opaque-first-linking.md)) and optionally syncs a biometric credential to the server afterwards.
- **Change passphrase.** Three branches: local-only, linked-online (full OPAQUE re-registration with staging-slot reconciliation per spec §5.7), linked-offline (blocked with a tooltip pointing back to settings).
- **PWA shell.** Manifest with maskable icons, soft-update banner driven by `vite-plugin-pwa`. Workbox runtime caching is fonts-only; every `/v1/` request is `NetworkOnly` (per spec §7.4 — no API responses cached).
- **Connectivity badge.** Five-state machine per spec §7.3 (`Local`, `Linked`, `Server unreachable`, `Server auth failed`, locally-logged-out implied).
